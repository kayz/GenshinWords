# 1.3.1 发布检查与后续方案

检查日期：2026-11-16。程序版本保持 1.3.1，不因为重新打包而任意增加版本号。资料包与程序版本分别管理。

## 本次分发范围

- Windows 安装程序内置 `genshinwords.base` 1.1.0，94 篇、523 题，最低程序版本 1.3.0，以及 11 本词书。
- 八个补充阅读包合计 1,101 篇、5,263 题。加上缺省包为 1,195 篇、5,786 道独立逻辑题。
- 安装程序仅纳入 `base.gwreading`，不会误带阅读目录中的旧批次或级别成品包。
- GitHub 只提交程序、工具和文档。本次 GitHub 版本说明也不附带安装程序或学习资源附件。下载仍使用 README 中维护者提供的地址。
- 本机重新制作的安装包尚需维护者上传网盘，GitHub 更新不会同步修改网盘文件。

运行 `node scripts/audit-release.cjs` 可重新检查九个阅读包的兼容版本、资源校验、段落及挖空映射、篇目/题号冲突，并输出数量、版本、SHA-256。输出摘要不包含题库正文。

## 内容质量边界

格式与判分校验通过不等于考试适配已经通过。当前八个补充包中，除雅思包使用 `tfng` 外，其余包的篇目类型都是 `reading`，问题主要为选择题。它们没有完整覆盖各考试的题型比例，不能宣传为完整模拟真题或整套考试训练。缺省包另有多种题型，不能用缺省包的覆盖范围代替补充包的实际情况。

抽看初中基础包发现对 `vanquished` 等难词的提问，仍需教师结合文章长度、句法、难词括注和答案依据复核。此次没有改写他人制作的题目，也没有逐篇完成 1,195 篇的语言与教学审核。题库数量应标为当前可加载库存，而非全部经过人工审定的推荐篇目。

建议后续为篇目另建内容审核记录，包含审核者、原文来源、难度依据、题型、答案依据、修改版本和审核日期，先审核再决定是否列入默认推荐。

## macOS 可行性

可以保留现有 `.gwreading`、`.gwwords`、`.gwcontent` 数据格式和相同文件。阅读包是 gzip JSON 与嵌入图片，词书/素材包是数据与媒体；SQLite 文件本身支持跨平台。目标是在 Windows 和 Mac 之间共享同一个资料包及 SHA-256。

程序仍需制作 macOS 专用安装产物，Windows EXE 无法在 macOS 原生执行。当前只配置了 Windows NSIS，尚未增加或验证 macOS 构建。

建议先提供 Apple Silicon arm64 的 DMG，再根据需要制作 Intel x64。需要在 Mac 构建机或 macOS CI 上安装依赖，针对架构重建 `better-sqlite3`、`sharp` 等原生模块，并完成签名、公证和真实 Mac 验收。现有 `darwin` 窗口关闭/激活行为已做基本兼容，但不足以证明可用。

Windows 在安装向导中选素材的 NSIS 页面不能复用于 DMG。Mac 建议首次运行进入内容管理，选择同一基础素材包或资源目录。另需检查大小写敏感路径、用户数据位置、中文字体、音频、PDF 和外接磁盘。不能直接复制包含 Windows 原生依赖的 `node_modules`。

参考：[electron-builder 跨平台构建](https://www.electron.build/docs/features/multi-platform-build/)、[Electron 原生模块](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules)、[SQLite 跨平台文件](https://www.sqlite.org/about.html)。

## 资料包保护

完全离线、用户机器可以展示原文并导出 PDF 的产品，无法保证内容不能被复制。加密包、关闭开发者工具或隐藏文件只能增加提取成本。当前 `.gwreading` 使用 gzip 压缩与哈希校验，没有加密、发行方数字签名、授权文件或设备绑定。哈希能查损坏，不能证明发行者身份，也不能阻止完整包复制。

建议按成本逐步处理：

1. 保留独立资料分发，在下载页、关于页和作者资料中明确来源、原创题目与解析的权利范围及分享规则。第三方原文、美术与词典不应声明为本项目独占资产。
2. 增加发行方数字签名，程序校验公开密钥以区分官方包与用户自制包。签名防冒充与篡改，不防复制。私钥只能存于发布环境，不能写入仓库或客户端。
3. 如确有定向分发需求，再增加不含个人姓名的发行编号和可见水印，支持 PDF 标注发行编号。需要说明编号只用于追踪版本/分发批次，不能承诺识别一切泄露。
4. 更强限制可采用加密内容及离线签名授权文件，绑定安装公钥并提供离线换机授权。这会改变现有开放资料包体验与格式，增加换机、学校机房、备份恢复和客服成本；仍不能防止授权设备截屏或导出。当前版本不实施这一层。

不建议为学生离线工具直接引入强制联网登录、硬件指纹和周期性激活。先明确需要防止的是冒充官方、整包二次出售，还是正常用户分享，再选择约束强度。

## 开源范围

建议公开阅读/学习引擎、题库格式、校验和制作工具、合成测试数据及文档。现有原文库、媒体、原创命题作者库和完整成品包继续站外管理。这样社区可以制作自己的内容，维护者也能独立维护现有题库。

当前仓库没有项目级 LICENSE，不能只因源码公开就称其获得了标准开源授权。需要维护者先选定许可证，逐项确认贡献者权利和第三方依赖要求，再增加正式许可证。本次不替维护者授予永久的 MIT、GPL 等新授权。

如果采用标准开源许可证，必须接受许可证允许的代码复制、修改和再分发；不能同时给同一代码添加“禁止一切商用或分发”的限制后仍称其为 OSI 开源。若希望限制这些用途，应使用清晰的源码可见授权，并将其与标准开源区别表述。源码许可不自动覆盖资料库或商标。

建议讨论 GPL-3.0 与 MIT/Apache-2.0 的取舍：前者要求分发衍生程序遵守相应源码义务，后者更宽松；二者都不能解决现有资料包的复制问题。商业条款与素材授权需由相应权利人确认。

参考：[没有许可证的公开仓库](https://choosealicense.com/no-permission/)、[OSI 开源定义](https://opensource.org/osd)。
